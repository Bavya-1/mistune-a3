# ADR-011: The planner moves from Gemini to Groq

## Status
Accepted. Supersedes the planner row of ADR-006.

## Context
ADR-006 chose Gemini Flash-class for the planner and warned that the first real
runs might force a change. They did (runs on issue #7, see `results/runs.md`):

- The Gemini model named in ADR-006 returned HTTP 404: it is closed to new accounts.
- The models still open had a very small daily request quota.
- We tried the Vercel AI Gateway (a friend's account) as a way around this. It
  answered HTTP 403 `customer_verification_required`: it needs a credit card
  on file, which we do not have and which would break the "free tiers only" rule.

Options: wait for quotas to reset and retry Gemini; pay; or use Groq, for which
we already hold a free key.

## Decision
The planner uses Groq `openai/gpt-oss-20b` (repository variables
`PLANNER_PROVIDER=groq`, `PLANNER_MODEL=openai/gpt-oss-20b`). The builder is
Groq `openai/gpt-oss-120b` and the reviewer is Groq `qwen/qwen3.8-27b`, as in
ADR-006. The code still supports the `gemini` and `gateway` providers.

## Consequences
- All three roles now use one provider. The planner and builder share the
  OpenAI model family (gpt-oss); the reviewer is still a different family
  (Qwen) with its own quota, so reviewer independence (ADR-008) is kept, but
  "three families" is no longer true.
- Groq allows only 8K tokens per minute, so the design stage had to be given a
  pre-built, size-limited context (`design_context` in `driver.py`).
- gpt-oss-20b on Groq often produced malformed tool calls or unparsable output
  (HTTP 400 `tool_use_failed` / `output_parse_failed`). In the five final runs
  this ended four of five runs before the builder started. A retry on these
  errors was written and then left out of the delivered code, so this remains
  an open weakness (see report, limitations).
- Related: ADR-006, ADR-008, ADR-009.
